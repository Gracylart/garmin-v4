2026-10-15 整理。当前 18 项、2,177 个源帧，源帧率均为 `30000/1001`，原生裁切坐标为 960 × 960。

| 分类 | 运动 |
| --- | --- |
| 常用 14 项 | 跑步、骑行、游泳、乒乓球、羽毛球、网球、篮球、足球、排球、高尔夫、公开水域游泳、赛艇、皮划艇激流回旋、拳击 |

## 源数据与二次创作

`sports-data/{id}.json` 是唯一的帧路径来源。每帧包含 `path`、`pixels`、`bbox`；文件包含 `fps`、`anchor`、原片时间和来源链接。`bbox` 的右边与下边不包含在像素范围内；填充使用 Canvas `Path2D` 和 `evenodd`。源帧顺序及起止空白帧保留，不能用几个姿态循环替代完整动作。

`sports-icons/group-{a,b}/manifest.json` 均指向根目录的 `sports-data/`，不重复保存路径。可编辑初始帧位于对应组的 `editable/`；任意源帧 SVG 也可由素材库导出。新增原创变体请使用独立 ID，保留来源与修改记录。

`reference-frames/{running,swimming,cycling,tabletennis}/` 保存四项早期对照 PNG，共 480 帧。旧 JSON URL 由预览服务器映射到统一数据目录。其余 14 项不附原视频 PNG，完整动作路径均已包含。

## 播放与时序

`SportsExact.ensure(id)` 按需加载完整数据。以静态锚点进入，源片末尾空白帧连接开头空白帧，再回到锚点；只压缩锚点相邻的连续静置段，后续重复姿态仍属于完整动作。

Studio 的转场内部 authored time 按 0.5 倍推进，当前脱轨入场为 1.08 s，初帧停留为 0.2 s。运动时长由源帧和运动速度决定；15/30 fps 只控制呈现采样，速度档只影响运动段。结束后静态姿态停留 0.7 s，再执行 1.16 s 融球返回与 0.9 s 眼睛停留。不要把运动速度乘到全局时钟上。

实验页另外保留融球铺屏和四面随机抛入拼装。关键帧弧长存储在 `emote-bounce-edit-v1`；主 Studio 的颜色与选择存储在 `emote-studio-v1`。这些浏览器存储不进入 Git，也不应在整理时清空。

## 固定视觉中心

`scripts/calibrate-sports-layout.py` 根据锚点的前景面积中心和边界框中心按 60/40 混合计算视觉中心，跑步、骑行的地面线也计入构图。每项得到固定的 `layout.x/y/s`，必要时还有 `ground`。这不是逐帧自动追踪，不会抵消原动作的伸展与位移。

`SportsExact.layout(id)` 为缩略图、源帧播放、脱轨目标和返回部件提供同一定位。修改构图时必须共同更新，不能只移动画布上最终的图片。乒乓球的球拍、球桌和人物原生几何继续共用一个变换。

## 验证范围

- `verify-sports-import.cjs`：18 项、2,177 帧、首尾空白、锚点、完整非静置帧、速度独立和有限几何。
- `verify-sports-layout.cjs`：视觉中心、缩略图与播放变换一致、入场与返回共用定位、脱轨目标位于真实轮廓、眼睛活动圆固定同心。
- `verify-project.cjs`：克隆后的 HTTP 页面、脚本、18 项数据、可编辑 SVG、审计链接、四组 PNG 与旧 URL 映射。
- `sports-icons/group-*/audit/`：之前提取阶段的历史轮廓审计。结论针对 `R<133 && B-R>12` 后的二值图形；不表示 RGB、视频压缩或 Garmin 渲染逐像素相同。本次整理未重新解码全片。

原片、ffmpeg、Python 图像依赖和完整提取环境不随仓库分发；这些不是运行当前 Studio 的依赖。手表端运动资源、内存、耗电和稳定帧率尚待单独实现与实测。
